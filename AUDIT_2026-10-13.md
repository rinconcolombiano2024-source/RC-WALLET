## Hallazgos confirmados mediante revisión de código

1. **Crash en ruta DEX sin mercado**: `src/market.js` leía
   `market.dexId` aunque el objeto puede ser `null` (sin liquidez,
   fallo DexScreener o carga pendiente). Cambio mínimo: acceso opcional.
   Incluido test de regresión.
2. **Escaneo obsoleto al cambiar de cuenta**: `src/App.jsx` rechazaba
   un nuevo escaneo cuando `scanning=true`, mientras uno anterior seguía
   activo. La nueva dirección podía conservar resultados previos. Ahora cada
   nuevo escaneo supera al anterior por `scanIdRef`; se ignoran respuestas
   de escaneos anteriores. Las solicitudes RPC pendientes aún consumen red:
   cancelación del transporte es tarea separada.
3. **Fallos ERC-20 informados como lectura correcta**:
   `src/blockchain.js` usaba `Promise.allSettled` pero no reflejaba
   rechazos de contratos en `networkStates`. Ahora marca `partial`,
   adjunta recuento de errores y advierte que no ver el activo NO prueba cero.
4. **Indicadores de prevalidación Safe potencialmente engañosos**:
   `src/safe-recovery-flow.js` y `src/App.jsx` anunciaban un owner
   "verificado" tras una prevalidación de forma/firma local. La verificación
   EIP-1271 en origen y la ejecución en destino ocurren más tarde. Se
   aclaran los mensajes: no prometer autoridad ni éxito antes de ejecutarla.
5. **SIWE con declaraciones de autenticación ambiguas**:
   `api/complete-siwe.js` probaba siete frases aunque `walletAuth` envía
   una sola. Ahora valida exactamente la declaración enviada en el frontend.
   Sigue requiriendo nonce HttpOnly y la firma verificada por MiniKit.
6. **Instalación no reproducible**: `package.json` usa Vite 7, React 19,
   Node 24; no existe `package-lock.json` en `main`. No existe CRACO
   ni react-scripts en la versión actual. Los errores históricos de AJV
   corresponden a otro árbol de dependencias: no hay evidencia de que
   permanezcan en el checkout actual. Se añade CI `npm ci` y una tarea
   temporal restringida a la rama para generar con npm el lockfile real.
   El lockfile fue generado por npm en GitHub Actions en la rama de revisión,
   nunca construido manualmente. Se elimina el workflow de bootstrap temporal.
   El build y auditoría de CI deben ser comprobados por separado.

7. **Cotización circular en DEX**: cuando el token seleccionado era
   la misma stablecoin que el token de cotización predeterminado, el enlace
   llevaba a intercambiar un token por sí mismo. Ahora se usa el wrapped
   token nativo como alternativa solo en este caso.

## Seguridad operativa

- Escanear una dirección **no** demuestra autoridad sobre sus activos.
- World Chain MiniKit no autoriza automáticamente firmas en otras redes.
- EOA, Safe y smart accounts necesitan validación de firma específica.
- La compatibilidad de una firma EIP-1271 aislada no equivale a autorización
  de ejecución Safe; confirmar nonce, threshold, dominio y simulación.
- World ID y SIWE prueban afirmaciones distintas; el flujo inspeccionado
  implementa SIWE, no una prueba biométrica de humanidad.

## Evidencia CI: auditoría de dependencias (13-10-2026)

GitHub Actions #38327812050: `npm ci`, sintaxis JS, tests y build de Vite
**pasaron**; `npm audit --audit-level=high` falló con **17 hallazgos,
15 moderados y 2 altos**. Los dos altos correspondían a `vite@7.0.0`
y `ws@8.17/8.18` transitivo (incluyendo dependencias de ethers,
viem y WalletConnect). No está relacionado con CRACO/AJV: esas dependencias
no aparecen en el árbol actual de 359 paquetes.

**Corrección controlada en rama (pendiente de CI):** subir Vite a
`7.3.7` (versión propuesta por npm audit) y fijar solo subdependencias
`ws` de ethers, viem y @walletconnect/utils a `8.21.0`, versión
con corrección documentada de CVE-2026-48779; conservar `ws@7.5.13`
para consumidores que requieren la rama 7. La actualización mantiene el
resto de la pila intacta y **no** utiliza `npm audit fix --force`.

Fuentes: https://github.com/advisories/GHSA-96hv-2xvq-fx4p y
https://github.com/advisories/GHSA-p9ff-h696-f583 .

El lockfile debe regenerarse con npm y las pruebas volver a ejecutarse;
no se da el problema por resuelto hasta que `npm audit` lo confirme.
